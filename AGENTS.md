# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this is

A local Kanban board for tracking Claude Code work. Each task can link to a Claude Code plan file (`~/.claude/plans/*.md`), a project directory, a GitHub PR, and a Claude Code session. The session id is found from Claude Code's transcripts in `~/.claude/projects/` so the board can run `claude --resume`.

Cost tracking (per-task cost badges and a weekly usage popup) was removed because it did not calculate correctly. Do not reintroduce it without checking with the user first.

The project is small and has no build step, no package manifest, and no test suite.

## Repository layout

| Path | Purpose |
| --- | --- |
| `server.py` | Python 3 stdlib HTTP server (`http.server`). Serves `index.html`, the JSON API, and reads Claude Code plan and session data from the home directory. |
| `index.html` | The entire frontend: HTML, CSS in a `<style>` block, and vanilla JavaScript in a `<script>` block. Loads Tailwind, marked and highlight.js from CDNs. |
| `tasks.json` | Board data (list of task objects). Written by the server. Personal data, and currently untracked. Do not commit it unless the user asks. |
| `data/` | Git-ignored. Board-owned plan snapshots (`data/plans/`) and logs (`data/logs/`). See "Plan snapshots". |
| `scripts/capture-plans.sh` | Bash. Copies Claude Code plans into `data/plans/`. Run by Claude Code hooks. |
| `scripts/install-launchd.sh`, `scripts/uninstall-launchd.sh` | Bash. Install or remove the macOS LaunchAgent that runs the server at login. |
| `.claude/settings.local.json` | Local Claude Code permissions. Leave alone unless asked. |
| `__pycache__/` | Generated bytecode. Git-ignored. |

## Running locally

The server runs as a LaunchAgent, `com.joseph.kanban-board`. It starts at login and restarts if it exits.

```bash
bash scripts/install-launchd.sh      # install or replace the agent (also starts it)
bash scripts/uninstall-launchd.sh    # stop and remove it
launchctl print gui/$(id -u)/com.joseph.kanban-board | grep -E "state|pid"
tail -f data/logs/server.log         # server output
```

- The server binds to `127.0.0.1:8765` (`PORT` in `server.py`). Only one process can hold that port, so stop any manual `python3 server.py` before relying on the agent.
- After editing `server.py`, restart the agent with `launchctl kickstart -k gui/$(id -u)/com.joseph.kanban-board`. A page reload is enough for `index.html`.
- To run without launchd for debugging, stop the agent first, then run `python3 server.py` in the foreground.
- There is no dependency install. Only the Python standard library is used. The frontend needs internet access for its CDN scripts.
- The LaunchAgent lives in `~/Library/LaunchAgents/`. Only the install and uninstall scripts touch it.

## Plan snapshots

Claude Code deletes old plans from `~/.claude/plans/`, so the board keeps its own copies in `data/plans/`.

- Each snapshot is `<hash>.md` (the content) plus `<hash>.json` (`hash`, `name`, `capturedAt`, `source`). The hash is the first 16 hex characters of SHA-256 over the bytes. Identical content is stored once.
- The `.json` file is the commit marker and is written last.
- Snapshots are written in four places: the Claude Code `Stop` and `SessionEnd` hooks run `scripts/capture-plans.sh` (a sweep of every plan file); linking a plan calls `POST /api/plan/capture`; saving a plan in the board calls `POST /api/plan`, which snapshots after writing; and the Python `snapshot_plan()` helper in `server.py` does the same work for the server paths.
- `GET /api/plan?file=<name>` returns the live file when it exists (`"source": "live"`). If it is gone, it returns the most recent snapshot with that name (`"source": "snapshot"` and `capturedAt`). Snapshot plans are read-only in the board.
- The hooks are registered in the global `~/.claude/settings.json`, not in this repo, because plans are created in every project. The hook must be a `bash` command that calls `scripts/capture-plans.sh`. Hook output must stay silent and the script must always exit 0.
- Test the capture script with `KANBAN_PLANS_DIR` and `KANBAN_DATA_DIR` set to temp directories. Never point tests at the real `~/.claude/plans/`.

## Testing and checks

There are no tests, linters or formatters configured. To verify a change:

- Python: `python3 -m py_compile server.py`
- Backend behaviour: with the agent running, call the endpoints with HTTPie, for example `http GET localhost:8765/api/tasks`. Use `http`, not `curl`, which is blocked in this environment.
- Frontend: start the server and exercise the board in a browser, including drag and drop, the task modal, the plan viewer and the settings pane. Say in your summary which checks you could not run.

## Architecture

### Backend (`server.py`)

- `read_tasks()` and `write_tasks()` read and write `tasks.json`. `POST /api/tasks` replaces the whole file with the request body. It does no validation.
- `/api/session` finds the most likely session for a task and returns only its id. It matches by plan filename, or by project directory overlap. It skips this board's own project folder.
- `/api/prs` shells out to `gh search prs --author @me` through `/bin/zsh -lc`.
- `/api/open-terminal` runs the posted `cmd` string through `/bin/zsh -lc` in a detached process.

### API

| Method | Path | Notes |
| --- | --- | --- |
| GET | `/`, `/index.html` | Serves `index.html` |
| GET | `/api/tasks` | Board data |
| POST | `/api/tasks` | Replace board data |
| GET | `/api/plans` | Plan filenames in `~/.claude/plans` |
| GET | `/api/plan?file=` | Plan content: live file, else latest snapshot. Returns `source` (`live` or `snapshot`) |
| POST | `/api/plan` | Overwrite an existing live plan file, then snapshot it (basename only, must exist) |
| POST | `/api/plan/capture` | Snapshot a plan now. Body `{"file": "..."}`. Returns `captured` and `capturedAt` |
| GET | `/api/claudemd` | Contents of `~/.claude/CLAUDE.md` |
| GET | `/api/prs` | Open PRs authored by the current `gh` user |
| GET | `/api/session?planFile=` or `?projectDir=` | Session id for the best matching transcript (`{"sessionId": ...}`) |
| POST | `/api/open-terminal` | Body `{"cmd": "..."}`. Runs the command in a new shell |

### Frontend (`index.html`)

- `COLUMNS` (around line 373) defines the board columns. The column ids used in `tasks.json` are `todo`, `inprogress`, `ready`, `done` and `archive`.
- Task state lives in a JS array loaded from `/api/tasks`. Changes go back through `saveTasks()`.
- Browser `localStorage` holds two keys: `theme` (`dark` or `light`) and `kanban-settings` (the terminal command preset, `CMD_PRESETS`).
- Rendering is string-built HTML (`cardHTML`, `buildColumn`). Use `escHtml()` for any user-supplied text placed into HTML.
- Drag and drop is native HTML5 (`onDragStart`, `onDrop`, `onCardDrop`).

### Task data shape

Each task object has: `id` (UUID), `title`, `description`, `column`, `projectDir`, `planFile`, `prUrl`, `color`, `createdAt` (ISO 8601). Keep this shape when you add or change fields, and handle older records that lack a new field.

## Conventions

- Match the existing style. `server.py` is plain Python with the standard library and no type hints. `index.html` is vanilla JS with no framework and no build.
- Do not add dependencies or a build step without asking.
- Commit messages are short, imperative and descriptive, for example `Remove session cost badges and weekly usage popup`. Keep that style.
- Do not use em dashes in code comments, UI copy or docs. Use a hyphen.

## Gotchas

- **Local-only, but not protected.** The server binds to `127.0.0.1`, but every response sends `Access-Control-Allow-Origin: *`, and `do_POST` does not check `Content-Type`. A web page open in the same browser could therefore send a plain POST to `/api/open-terminal` and run a shell command, or overwrite `tasks.json` through `/api/tasks`. Treat any change to these endpoints as security-sensitive. Do not widen them further.
- `POST /api/tasks` overwrites the whole file. Read, modify and write the full array. Do not send partial data.
- `/api/plan` POST only overwrites plans that already exist. It cannot create new files.
- Plan and project matching is heuristic. Session matching scores directory name overlap, so a wrong session can be chosen when names are similar.
- `tasks.json` contains real project paths and personal task titles. Do not paste its contents into commits, PRs or logs.
